Component context

One <logged-days> component, two hosts. It declares no store of its own — it inherits one under the alias data, plus a plain string loggedKey telling it which key to read. The child source mentions neither meals nor workouts.

What to check

  1. Each child lists its own host's dates, and names a different loggedKey.
  2. Clicking a host's button adds 2026-09-06 and the child updates on its own — it is subscribed to the inherited store, not re-rendered by the parent.
  3. Only the clicked host's child changes.
  4. The workout host declares a store in its manifest and returns one from getStores(). Both resolve; the click counter proves the second one is live.
  5. The console must be clean. Coexisting sources no longer warn — only a real key collision does.

Keyed reordering

Click a few chips in each row to give them different counts, then reverse. Keyed chips keep their count with their label because the elements were moved. Unkeyed chips do not — positional matching replaced them, which for a nested component means losing its shadow root, subscriptions and state.
